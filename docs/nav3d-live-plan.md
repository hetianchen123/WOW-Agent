## 已实现的数据链

`本机 .build.info → CASC → Map.db2 → WDT → ADT 地形与实例 → WMO / M2 碰撞 → 局部 Recast → Detour 完整路径 → TravelCommand`

- 固定 CascLib、wow.export、Map.dbd 版本；构建与只读补丁见 `native/nav3d/casc/README.md`。无 API 密钥依赖。
- CASC 按产品 `wow` 选择本地构建。严格读取校验，不联网补资产、不将缺密钥内容填零。缓存按 Build Key 隔离，读回校验摘要。
- `Map.db2` 解析世界地图身份、Directory 和 WDT FileDataID；WDT 给出实际 tile 文件 ID。uiMapID 只用于界面与同帧一致性，不作资产世界 ID。
- 地形保留高度、低/高精度洞口。ADT 水域按 MH2O 实际湿格排除，缺少有效覆盖信息时排除相应 chunk。ROI 内有 WMO 水体时停止提取。WMO 使用碰撞及普通渲染面标志，排除 detail 面和 MOGP 不可达或 antiportal group（0x80、0x4000000 或 antiportal 名称），兼容 16/32 位索引与新材质标志。M2 使用碰撞顶点和索引。
- 应用 ADT 实例的位移、旋转和缩放；包含 WMO 全局与选定 doodad set 的 M2 碰撞。实例、源文件、依赖、变换与摘要逐项落盘。邻接 tile 也检查可能跨界的摆放。现代 FileDataID 为主要路径；旧名称索引可显式提供 listfile。
- 三角形裁切到 ROI 后构网。首轮使用起终点包围框加 32 码，最大边长 320 码，仍受四百万水平体素上限约束。没有生成全世界导航网格。
- 不支持的全局 WMO 地图、水体、缺资源、未知模型结构均报错。动态门、运输载具、任务相位替换等不在静态资源证明范围内，不能因此认为当前场景已可通行。

## 遥测与运行边界

插件版本 `0.2.75`。旧旅行 v15/schema 6 保留；新增 `Nav3D.lua` 独立 schema 1，放在主色条右侧 288 像素处，共 26 行。每行 20 位载荷：低 12 位数据、高 8 位序列；跨行序列必须一致。坐标为带符号 24 位百分之一码，字段含世界 ID、build、uiMap、玩家 XYZ、朝向、任务与阶段、世界目标 XY、状态。截取旧旅行与三维通道的同一张图，核验序列、任务、阶段和 uiMap。

`east_north_up = (-UnitPosition 的第二返回值, 第一返回值, Z)`。目标用 `C_Map.GetWorldPosFromMapPos` 转换，返回世界 ID 必须一致。数值、缺失和受限分别编码；公开高度 0 不自动标为可靠地板高度，也不泛化为所有区域都无效。

本机当前位置只有 XY 可用于可靠定位，Z 用网格唯一支撑面初始化。后续要求短距离、连续高度且能通过同一导航网格连接；找不到支撑面或出现上下层歧义即停。日志标记 `inferred_mesh_support`，不把推导高度写成原生实测。

`config/bot.yaml` 当前选择人工监督 `nav3d` 试跑：

| 模式 | 行为 |
| --- | --- |
| `visual` | 显式使用旧流程 |
| `nav3d-shadow` | 在旧恢复/建筑/接近/战斗动作前接管，只规划、记录并停止，不发送移动 |
| `nav3d` | 三维协调器唯一负责本轮地面导航，经原 `apply_travel_command` / helper 执行；没有对齐证据或显式绑定网格的监督试跑配置时拒绝移动 |

预算固定上限 120 秒、最多 3 次恢复；候选切换不重置预算。目标层按高度升序尝试，不以最短路线替代顺序。规划不连通或执行卡住会记录原因并切换下一层；传感器失联、帧身份改变或异常位移仍立即停机。普通任务到路线末端释放按键等待目标回执；回执不足继续上层，明确回执则停在 `nav3d_target_reached_waiting_task_execution`，完整战斗/交互链尚未接通。

常规已标定运行需 `alignment_file` 绑定 mesh_id、frame，标注 `evidence_kind=live_observation`、`alignment_verified=true`、`phase_verified=true` 和实际 receipts（每项为相对文件路径、SHA-256、kind；需 `native_xy_alignment` 与 `scene_phase` 两类，逐项核验文件摘要）。当前没有伪造这类证据。用户要求人工启动测试，因此新增 `supervised_trial_mesh_id`，只有与加载网格 SHA-256 完全一致才允许未标定试跑；日志仍明确 alignment/phase 未验证，不改 helper 授权、前台或急停。清空该字段即恢复严格证据门槛。`phase_id=quest:90896:2` 是本轮任务场景标签，不是游戏公开提供的物理相位 ID；物理相位仍须实景核验。

本轮验证：1244 项 Python 全量回归通过；补齐位置/控制日志与实际输入入口检查后 77 项三维定向回归通过。上轮 8 个 Lua 回归通过，本轮未修改插件。合成几何、协议与命令生成检查均不计作实走。

### 设计的最小任务流程（落地状态见下节）

`三维接近 → 确认目标区域 → 原地等待刷新 → 精确选中并核验 → 首次攻击 → 持续输出 → 核验任务进度`

1. **目标与准备**：从当前任务目标文本读取本地化名字；必要时用本机目标公开身份补全 NPC ID。脱战准备独立的精确选怪安全按钮，宏只选择该名字，不混入攻击；增加可核验的绑定/目标资料回执。插件只读状态，实际按键仍由原 helper 会话执行。
2. **等待刷新**：有区域/场景依据后释放移动，固定等待点，保留本轮楼层支撑和已走路径。独立可配置等待预算，首版建议 300 秒，这不是刷新周期。以约 0.2 秒的有界选怪间隔检测目标；记录首次观察、可攻击时刻。区分未出现、尸体、活着但不可攻击、已可攻击。不反复跑楼层、乱 Tab 或扫屏。若只有不确定的地图针，仍按候选探索，不能自动断言这里就是刷新点。
3. **及时首击**：新序列核实目标与任务一致、活着、可攻击、绑定有效、技能范围明确可用后立刻进入输出。选择和攻击分开核验；同目标锁定 GUID/epoch。首版争取一个遥测更新周期内响应，但测量实际延迟，不承诺零延迟。范围未知、不可攻击、视线错误不能用无界连按掩盖。
4. **状态交接**：入战时由任务战斗/自卫接管，先释放导航；普通入战不结束整轮任务。死亡、失去焦点、键位变化、未知世界等仍独立停止。战斗中的接近仍受三维通路约束，不接回旧的直线穿墙接近。
5. **结果判定**：保持同目标持续输出，读取施法/掉血/任务计数。死亡或消失但仍 0/1，保留未完成并进入有限等待，不算成功。任务计数 1/1 或可交付才转入交付流程。交付萨尔需另一段世界路线；当前局部建筑网格不代表全程交付已可走。
