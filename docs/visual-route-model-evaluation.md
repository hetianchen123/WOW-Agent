本轮目标是检验模型是否能从截图自行生成绕障路线，不再用固定左右偏移的模拟成功代表模型规划能力。仅离线推理，没有发送游戏输入。当前栅栏交付仍未实机通过。

## 先核对当前实现

`bot/control/local_bypass.py` 的左右折线来自世界坐标和固定侧偏；它是有位移反馈的规则候选，不是视觉模型画出的路线。`experiments/qwen3_vl/run.py` 的生产提示词主要输出短步通行状态和观察点，也没有完整路线接口。StartLux 在候选内选择不会自行补出未提供的路线。

因此存在两个独立缺口：规划接口没有承担真正找路；视觉模型也尚未通过当前障碍的定位、轮廓与路径验证。

## 可复现方法

评测程序：`experiments/route_models/compare.py`。输入为 21:37 实际窗口截图和 19:17 右视角场景图；不包含用户绘制的红箭头。图片、源文件 SHA256、裁剪变换、提示词、模型标识、时延、token 数、原文、解析错误和叠加图保存在 `data/terrain/model-route-comparison-20261116/`。

所有基线使用相同提示词、图像、temperature=0、最多 1200 个输出 token；要求自行定位玩家脚点、指定 NPC、障碍轮廓和最多七个路径点，不提供路线方向或偏移量。局部放大实验统一裁取同帧 `(220,300,700,540)` 区域并放大两倍，不增加路线标注。9B 推理模式单独记录为额外实验，不与基线速度作严格同条件比较。

示例（仓库根目录）：

```sh
data/startlux/.venv/bin/python experiments/route_models/compare.py \
  --backend mlx --model data/qwen3-vl/model --label qwen3vl-8b
```

程序还支持本机 OpenAI 兼容服务、Ollama、局部放大及镜像输入。坐标解析通过只说明格式可用；叠加图必须独立检查。镜像模式同步翻转目标的左右描述，本轮尚未运行镜像对照。屏幕路径不能直接当世界坐标或作为发键授权。

## 初步结果与边界

- **Qwen3-VL-8B，现用 4bit，MLX**：宽图两张约 17 秒/张，玩家/NPC 脚点与实际位置不符，障碍框落错，路线未绕开实际木桩。局部放大后 19:17 图角色定位改善，但路线仍横穿木桩；两张局部图约 17 秒/张。不能接入为可靠路线规划器。
- **Qwen3.5-9B，4bit，直接 MLX 视觉推理**：宽图约 17–20 秒/张，仍将目标放到问号/上方地面附近，障碍框不对应实际阻挡，路线穿过木桩。不是可直接替换的修复。
- **Qwen3-VL-4B，4bit，MLX**：宽图约 10 秒/张，返回扁平数组而非要求的多边形坐标；同时存在角色错认、目标脚点偏移，不能仅靠修 JSON 得到可用路线。
- **9B 服务配置问题**：本机 oMLX 对该模型设置了 `model_type_override=llm`。经其 HTTP 接口运行两张不同图时，输入均为 380 token，输出完全相同；直接 MLX 视觉模式输入为 958 token，输出随图片改变。原服务结果不计入视觉能力比较。本轮没有修改供其他用途使用的服务配置。

上述属于少量真实截图的离线失败样本，不能推导“所有本地模型永远做不到”，也没有完整任务成功率。手工查看叠加图发现的错误是视觉复核结果，不是游戏碰撞验证。宽图与局部图都失败，也不证明多帧观测或更强模型必然失败。

## 最终实现：一次生成路线，本地完整执行

用户在本轮进一步明确：每小步请求模型浪费 token，应一次规划完整路径，脚本转为坐标和方向执行。已据此替换早期逐步方案。

- `bot/decision/route_planner.py`：DeepSeek 官方 `deepseek-flash` 视觉 API；同帧宽图/细节、坐标、目标距离与方向、碰撞格和失败历史。每次最多 1600 输出 token，默认非推理；低推理模式可独立测试。
- `bot/control/model_detour.py`：最多 6 个模型路点；以当前位置为原点、目标方向为前轴、顺时针垂直为右轴，按模型给出的码数和地图实际长宽转换。不是像素直接变世界坐标，也不是固定侧偏。
- 一次模型返回后，本地闭环连续执行整个候选路径；每次转向/前进不调用 API。只在碰撞、偏离、路径耗尽仍无原生范围回执时重拍/重规划；最多 3 次请求，总卡点预算保持 60 秒。
- 启用项目 `route_planner` 后，NPC 接触退离出口优先模型路线，不再先走固定左右折线；非接触的 NPC 接近失败同样可进入模型观察。当前没有把这套 NPC 判据套用到所有旅行、飞行或战斗。
- 姿态、帧、时效、任务、异常状态、实际位移、高度、失败路段及原生范围分别检查。正常位置回执不代表整个候选路线已验证；不因模型声称到达而交付任务。
- 用户指定的项目密钥已用于真实 API 评测，不输出、不打包、不存入运行配置；`deepseek/apikey.txt` 已被 git 忽略。官方图像接口依据：[Vision](https://api-docs.deepseek.com/guides/vision/)，推理开关依据：[Thinking mode](https://api-docs.deepseek.com/guides/thinking_mode/)。

## DeepSeek 真实请求结果

早期逐步方案测试在 `deepseek-production.json`，不作为最终方案。最终完整路线使用 19:17 原图、该曝光的实际位置/朝向和同轮目标坐标，见 `deepseek-batch.json`：约 2.46 秒，输入 1683、输出 268、合计 1951 token。返回路线穿过它自己标出的障碍，被校验拒绝；并且玩家/NPC 脚点仍有偏差。

一次反馈重规划见 `deepseek-batch-retry.json`，约 1.98 秒，仍被首段穿障检查拒绝。低强度推理另测 `deepseek-batch-thinking.json`，约 14.39 秒耗尽 2400 输出 token，没有完整结果。没有通过放宽碰撞检查将失败标成成功。

本机 Ollama 4B 另测两张局部图约 12.9–14.7 秒，仍有多边形格式错误；现用 8B 的两张局部图约 17 秒，虽改善角色定位仍穿木桩。9B 局部推理两张约 110.7/114.4 秒均耗尽 2600 输出 token，无法作为当前恢复预算下的方案。

**当前结论**：一次规划、脚本整段执行的控制流已经实现；真实 DeepSeek 栅栏路线尚未通过，不能宣称换模型已解决实机问题。下一关是用保留截图取得正确的障碍端部、脚点与完整路线，再核对度量估计与实际位移，最后才进行交付/接续验收。任务范围仍不包含未验证的跨层路线。

行为回归与真实模型结果分开统计：本批新增评测器 9 项、模型路线控制器 16 项；全量 Python 463 项、Lua 6 个脚本通过（后续变更按发布验证记录更新）。模拟证明一次计划能驱动多个路点及碰撞后的二次计划，不能证明实际模型给出的路能走通。

补充取景实验：同一 19:17 图仅保留纵向 35%–94% 地面区域，再提供同帧细节和实际接触/退离事实，仍被第一段穿障检查拒绝。证据 `data/terrain/deepseek_20261116_223153_7b4f440c/`。没有将这个未改善结果的裁剪替换生产取景。

最终验证：468 Python、6 Lua；其中本批控制器 21 项、评测器 9 项。当前源码为可审查的候选实现，模型路线质量仍未过关，不把此版本宣传为已修复实机绕障。

## 2026-11-17：冻结定位、独立轮廓复核与完整路线回放

**用户要求**：先用截图反复验证，将实际模型路线画出来，确认绕过栅栏再安排实测。本批没有发送游戏输入；两次只读窗口清单均未发现可见魔兽窗口，因此不能把保留图片称为当前实时画面。

### 修复内容

1. `grounded_route.py` 从已核对任务登记表取得目标 NPC；同一曝光分别放大中央玩家及黄色问号下的 NPC 候选，每张独立识别。裁剪偏移仅用于本地变换、留在日志中，不发送给模型；玩家识别请求也不混入目标 NPC 名称。此前模型曾把原图裁剪框直接抄成局部图坐标。
2. 障碍识别要求覆盖斜木桩与立柱底部，生成保守边界，再冻结脚点和边界供一次完整路径规划。规划器不能移动脚点、缩小障碍来通过自己的检查。所有路线均检查角色半径、有效画面边界及简单多边形。
3. 起点已经贴近边界时，只允许第一段沿边界外侧增加距离并恢复余量；禁止穿过实体或贴边滑行。向模型提供数值约束，不提供预定绕行方向或完整折线。六次回放中的第 3、6 次实际产生了先退离余量、再绕端部的路线。
4. 取消独立生成第二套世界路点：从同一图像路径、已知目标距离及保存视角俯角估计局部平面坐标。额外核对图像/世界路点绕行侧一致。该转换仍是近距离平地近似，不能称为精确深度或已验证世界路线。实际移动反馈仍由原控制器确认。
5. 无效候选也画出原始路径并保留全部阶段请求、原文、token、错误。被拒绝时不由绘图器修正路线。新错误区分 `route_pixel_outside_ground_frame`，不再将越界混成格式错误。

### 图像到世界坐标：新增可检验的标定模块

`ground_projection.py` 使用同一参考图中的地面点与原生世界坐标对应，拟合局部平面单应变换。至少 6 个拟合点覆盖二维区域，另需至少 3 个空间分散、未参与拟合的验证点；单向前后移动、重复验证点、模型估计坐标不能通过。拟合最大误差限制 0.2 码、独立验证最大误差 0.25 码，数值阈值仍待实机校准，并非已证明的控制精度。

变换绑定图片哈希、地图、明确层级、画面大小、玩家脚点/世界位置、高度、朝向、镜头槽位/距离/epoch/FOV和采样时间。路线禁止越出标定点包围区域，旧画面、镜头/姿态变化及过长移动拒绝。离线导出世界坐标、每段码数和目标朝向，可以与现有世界路点执行器对接；输出仍 `executable=false`，尚未接通运行时放行。

`projection_replay.py --bundle <JSON> --output <JSON>` 为离线入口；数据格式见脚本头部。`synthetic-projection-bundle.json` / `synthetic-world-route.json` 只验证透视、旋转、不同地图长宽的数学转换，绝不是当前游戏坐标。用户俯视截图缺少同曝光原生世界姿态和地面对应点，不能拿旧低角度日志补造标定。

真实标定采集尚待实现/验证：在可见、已确认同一地面的区域保持俯视构图，绑定每次新序列的原生位置；将各位置的实际地面接触点对应回同一参考图，保留追踪/人工复核依据，留出额外位置独立验证。自动跟随相机使角色中心近似固定，**屏幕中心不能提供这些地面对应点**；需要追踪静态地面或经核对的地标，并排除木桩、NPC、宠物等非地面特征。通过这一关后，再进行短段真实位移核验，最后才解除俯视移动门槛。

本批 539 Python、6 Lua 通过；新接口/投影共 18 项行为回归。无插件变更，无游戏输入。GLM 视觉质量和实机投影均未通过验收。

## Coding Plan 复核与模型结论（2026-11-17）

用户确认使用 Coding Plan。更正上节：标准 API 的 1113 不能证明 Coding Plan 套餐欠费；两者计费入口不同。按[官方工具说明](https://docs.bigmodel.cn/cn/coding-plan/tool/opencode)使用隔离安装的 OpenCode 1.19.5 完成开发评测，工具调用全部禁用，不接入 WowAgent 运行时。生产客户端仍使用标准 API；套餐不能直接视作自建机器人运行额度，见[使用说明](https://docs.bigmodel.cn/cn/coding-plan/usage-notes)。

修复开发客户端步骤上限导致的首轮强制总结，增加显式 `--variant low` 和固定标题，避免自动标题调用。旧客户端六次复杂请求均超过 110 秒，没有完整结果；保留为客户端/时限失败，不能按视觉识别错误计数。显式 low 后获得如下实际结果，均不是游戏实测：

| 实验 | 结果 | 耗时 / token |
| --- | --- | --- |
| GLM-5.3 文本控制、Flash 合成图片控制 | 均通过 | 2.73 s / 203；3.56 s / 542；早期控制用量未计额外标题请求 |
| Flash 自主观察同一俯视图，3 次 | 全部未产出可用地图；栅栏邻域召回 41.8%、47.3%、30.9%，IoU 18.1%、42.8%、11.4% | 28.60、29.37、37.99 s；2669、2692、3045 token |
| GLM-5.3，提供人工复核几何，一次 | 5 点完整路线通过给定图像地图几何检查 | 103.87 s / 5779 token |
| Flash，提供相同人工复核几何，一次 | 给定图像地图几何检查通过 | 30.38 s / 1818 token |
| 官方视觉 MCP 0.1.6，同图完整地图，一次 | 客户端约 112 s 超时，无完整输出，不评价识别质量 | 无有效用量回执 |

Flash 三次玩家脚点误差 3.0–4.5 px，NPC 脚点误差 9.2–11.7 px；主要问题是完整栅栏边界偏移/漏检、灌木与未知地面混淆。首次地图包含 x=1012/y=586 的越界边界，触发 `image_polygon_invalid`；随后两次 `image_start_blocked_or_uncertain`。没有裁剪修补错误输出或把拒绝结果当成无路。独立人工标签只用于评分，未输入地图识别模型。

所有提示、输出、叠加图和用量位于 `data/terrain/glm-coding-evaluation-20261117/`。`explicit-low-map` 与 `explicit-low-map-repeat` 是三次有效自主观察；`explicit-low-geometry` 与 `flash-geometry` 为人工输入隔离实验。原始超时和客户端配置失败保留在其他子目录。给定地图的通过只证明绕开已标注木栏；地面矩形仍是实验假定，灌木实际通行性、世界投影及真实位移未验证。
