# 任务模块

## 跑尸与复活准备

插件 0.2.45 在已准备的任务会话中支持释放灵魂、步行跑尸和确认复活。跑尸使用同一帧的地图位置和朝向，单独核对步行键。优先使用游戏提供的尸体坐标或追踪路线点。缺坐标时，从校准过的小地图识别唯一墓碑并在两帧间核对位置。仅有追踪距离时，在同一地图短距离采样以估计方向，再验证剩余距离确实缩短。`quest_recovery_route` 记录目标来源，`quest_recovery_route_wait` 记录缺失项。进入复活范围后停步，只点击已识别且可用的原生按钮。复活后确认宠物和 Buff 状态，再重新规划当前任务。副本入口、跨地图路线和游泳需要额外适配。

猎人沿用存活宠物并令其跟随，缺宠物时从有宠物的召唤栏位选取一个，已死亡的宠物优先复活。术士默认选已学会的恶魔卫士或小鬼。法师、牧师、德鲁伊和战士会补缺失的默认职业 Buff。可用 `/wagent quest recovery pet <召唤技能ID>` 和 `/wagent quest recovery buff <技能ID> [光环ID]` 配置当前角色，填 0 恢复默认。修改后重新准备任务，插件会核对并按需临时覆盖 F9–F12。

这套流程已通过模拟验证，需在游戏重载插件后实测。相关日志以 `quest_recovery_` 开头。

脚本操作准则统一维护在 [wow-playbook skill](../skills/wow-playbook/SKILL.md)，包含旅行避障、战斗与拾取、任务轮次以及实机验证规则。规则中的开发目标与已实测能力分别标注。

目标搜索取消整屏鼠标网格降级，以及找怪失败后改扫物件的流程。物件鼠标定位仅使用已识别候选或游戏确认的位置，每轮最多 6 个；没有屏幕候选则报告 `quest_object_visual_target_required`。找怪、NPC 搜索和战斗朝向纠正改为间隔至少 0.45 秒的短转向，到向后停稳再操作，避免频繁左右晃动。本次为 Python 更新，新主控会话生效；实机效果待确认。

2026-11-12 拾回流程修正：已确认战斗结束且拾回已准备时，即使尸体可拾取标志为 false，也允许一次 L 尝试。按键后等待任务进度或同一尸体可拾取状态从 true 变为 false；不将持续 false 当成拾取成功。无反馈时最多等待 8 秒，再进入原有回退或停止流程。本次只改本地主控 Python，新会话生效，无需因此重载插件；自动拾回实机结果仍待核对。

插件从任务日志和当前 NPC 对话读取任务 ID、分类、可交付状态和单目标计数。执行器按计划里的顺序推进，重新启动时会跳过服务器已标记完成的任务。任务色条独立于原有色条，默认隐藏。

| 读取结果 | 分类依据 |
| --- | --- |
| `CAMPAIGN` 战役 | 游戏分类、任务日志的战役 ID 或任务线的战役标记 |
| `MAINLINE` 主线候选 | 任务日志标为剧情任务，且任务线未标为地区故事 |
| `SIDE` 支线候选 | 地区故事，或已有标题或日志记录的普通任务 |
| `WORLD`、`REPEATABLE` | 世界任务、重复任务和召唤分别归入对应类别 |
| `IMPORTANT`、`SPECIAL`、`UNKNOWN` | 重要任务、特殊任务，以及分类信息不足的任务分别显示 |

主线和支线是项目根据游戏元数据推断的分类。老资料片和特殊任务可能需要任务 ID 白名单来消除歧义。任务计划本身就是可执行 ID 白名单，分类筛选会再检查一遍。[暴雪任务日志 API](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua) · [暴雪任务线 API](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLineInfoDocumentation.lua)

## 查看当前任务

1. 更新 `WowAgent` 插件后在游戏里执行 `/reload`。
2. 执行 `/wagent quest scan`。它会开启五行任务色条，轮询任务日志和当前 NPC 的任务列表。
3. 保持游戏画面和两块色条可见，运行 `uv run python -m bot.cli probe-quests --duration 20`。观察输出中的 `id`、`kind`、`state` 和 `progress`。
4. 执行 `/wagent quest off` 可关闭任务色条。

## 本地自动接任务测试

任务运行由脚本读取色条，向 `127.0.0.1:8090` 上的本地 StartLux 提交结构化状态和候选，取得阶段选择后执行既定路线或按键。模型调用在独立线程中运行，脚本持续检查色条、游戏焦点和停止条件。模型低置信度、超时、服务不可用或返回时状态过期都会停止本次执行。

1. 在游戏中打开 NPC 的未接任务对话，打开 WowAgent 的「任务与色条」页。只有一个可接任务时可留空任务输入，有多个时从列表选择一个。
2. 点「准备自动接任务」。插件把该任务的操作宏放到数字键 9 对应的主栏空位，并开启该任务色条。
3. 在「WoW 键鼠」菜单启用一次会话，然后双击 `macos/quest-accept.command`。启动器加载已安装的本地模型并打开主 App，脚本会自动切回游戏。保持 NPC 对话打开；系统未自动切换时，在 12 秒内手动切回。
4. 本地 StartLux 选择接取后，脚本按键推进任务详情和接受。只有任务日志实际变为已接取或可交付，才报告 `quest_accept_confirmed` 和 `completed`。

主 App 也可直接运行 `accept-quest`，此时需先按 [本地模型启动方法](startlux-poc.md) 启动服务。使用双击启动器时，任务结束后会关闭本次主控和启动器自己启动的模型进程。

2026-11-07 在正式服实测任务 90882「若是那豺狼来了」接取成功。地图为 2451，插件分类为 CAMPAIGN。脚本读取任务详情后请求本地 StartLux，模型选择接取，随后按数字键 9。任务色条从 PENDING / DETAIL 变为 ACTIVE / CLOSED，目标进度为 0/10。会话结果为 `completed`、`quests_accepted=1`，总用时 1.7 秒，其中模型请求约 784 ms。完整记录存于 `data/reports/quest-90882-live-accept.json`。目标击杀和交付继续单独验收。

准备失败时，面板会分别报告键位未绑定、格子占用、宏位已满、游戏拒绝创建宏或宏内容核对失败。宏位已满会显示角色和账号两类容量。角色宏位满而账号仍有空位时，插件会改用账号宏位。

## 执行一条已配置的任务线

正式服插件 0.2.8 增加了「任务寻路」。重载后在该页选择已接取的任务，坐骑可保留自动选择。点「准备任务寻路」后，启用键鼠会话并双击 `macos/quest-navigate.command`。本地主控也可直接运行 `navigate-quest`。添加 `--travel-only` 会在到达并确认落地、下马后结束。添加 `--dry-run` 使用模拟输入。

从 0.2.11 起，寻路会读取游戏里的「坐下／下降」绑定。飞行可用时，插件会使用核对过的单键，例如 `C`、`F6` 或下方向键。没有可用的下降键时，仍可准备任务并使用地面坐骑或步行。

在「任务寻路」的「任务键位」里选择「准备时启用临时任务键位」，然后点「准备任务寻路」。插件会核对移动键、Tab 选敌、F 互动和数字键动作栏。关闭寻路色条、交付任务或重载界面会恢复临时覆盖的原键位。「查看任务键位」可查看当前绑定。

同页的「启用游戏互动键」控制暴雪的互动设置。它是独立于临时键位的游戏选项，关闭寻路色条后仍会保留，可从同一个按钮停用。自动交付前，脚本会靠近地图标记，选中已确认的交付 NPC，然后短步靠近。只有游戏距离检查确认 NPC 在 5 码内才按 F。距离未知时不会尝试对话，后续对话也会核对任务 ID。

### 直接在本机运行

1. 已打开任务详情或 NPC 的任务列表时，点「一键准备自动任务」。也可以点「准备附近任务」，从同地图起点 400 码内的游戏任务标记和 NPC 对话发现普通剧情任务。
2. 等面板确认成功后关闭面板。插件会核对宏、临时键位及游戏的互动和自动拾取选项。交付时可以用 NPC 名称作为额外校验，缺省时使用游戏交付标记和对话中的任务 ID。
3. 保持魔兽在前台，在 macOS 菜单栏「WoW 键鼠」点「授权并运行已准备任务」。首次运行按 macOS 提示授权后切回魔兽。本地助手会启动 StartLux 和任务主控，菜单提供运行状态、日志和「立即停止」。

| 快捷键 | 用途 |
| --- | --- |
| W / S / 左右方向 / 空格 | 前进、后退、转向、跳跃和起飞 |
| Tab / 1 | 选敌和辅助输出 |
| 5 / 6 / 7 / 8 | 飞行风格、飞行坐骑、地面坐骑和下马 |
| K / F / 9 | 选中已识别的交付 NPC、互动、推进对应任务对话 |
| F | 对当前战斗中已确认、进入拾取范围的尸体互动，由游戏自动拾取 |
| J | 使用任务日志提供的专用道具。默认只绑定，选择「自动使用无目标道具」后才会在到点后使用 |

自动执行未配置任务时，脚本使用游戏给出的同地图坐标。单目标的击杀、掉落和物件互动需要游戏提示能与当前任务目标匹配。脚本通过任务日志确认进度与交付。多目标组合、需要特殊动作或选择奖励的步骤会暂停。完成任务或在插件中关闭寻路色条会恢复临时键位；互动和自动拾取属于保留的游戏设置。

自动模式按轮执行。先接完本轮可发现的附近任务，再逐个做目标，最后集中交付。刚接取就可交的任务会优先交付，先处理它在当前对话弹出的后续任务，再继续收集本轮任务。普通任务的后续会留到下一轮。每轮交付结束后从当前位置再次扫描。中断后重新准备可继续本轮阶段。自动模式单次默认最多运行一小时。

上飞行坐骑并切换到驭空术动作栏后，插件会按技能核对当前可用的升空和急停键，优先读取默认的 1–5。准备任务时，插件会尝试沿用可识别的俯冲键，再从空闲键和主栏第 10、11 个空格中选择临时键。动作栏切换后如果借用的格子被占用，插件会撤销临时绑定。关闭寻路色条也会解除临时绑定。

插件读取任务航点和地图标记。脚本按飞行、地面坐骑、步行的顺序选择。飞行使用稳速飞行，检测到天空骑术时尝试切换，等到状态确认后起飞。地面路线用实测位置发现卡阻，有限次数内绕行。坐骑召唤超时会降级，落地超时会停止。跨地图或任务坐标不可用时，运行结果会给出停止原因。

准备寻路会核对一键输出 1、任务交互 9 和旅行宏 5–8。移动需要 W/S、左右转向键、空格和 X。交付阶段会核对 F 是否绑定为与目标互动。可运行 `probe-navigation` 只读检查目标位置和移动能力。

自动推进的首个计数击杀任务是 90882「若是那豺狼来了」。抵达目标区域后用任务允许的怪物名单选敌，按日志计数确认击杀。可交付后改读交付目标。游戏要求从多个奖励中选择时暂停并报告。其它任务可先用 `--travel-only` 验证寻路，再补对应的执行配置。[客户端任务坐标接口](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua)

已有 YAML 计划仍可用 `run --module quest` 执行实测的同地图地面航点。路线适合对话、到达、有明确交互对象的单目标任务，以及配置了目标白名单的计数击杀任务。遇到多目标、计划外战斗、意外对话、多个可选奖励、色条失联或游戏失焦时，脚本会停止或等待后停止。

以下文件只是格式示例。将 ID、地图、航点和按键换成实测值。

```yaml
map_id: 2248
quests:
  - id: 12345
    dialog_key: "9"
    pickup: [[0.4000, 0.5000]]
    objective: [[0.4010, 0.5010]]
    objective_key: "8"
    turn_in: [[0.4020, 0.5020]]
```

- 每个任务的 `dialog_key` 绑定一条固定 ID 的游戏宏，例如 `/run WowAgent.QuestAction(12345)`。插件按键时再次核对对话里的任务 ID。一个对话列出多个已跟踪的候选时，先人工选中正确任务。
- 游戏里的 `f` 绑定交互键，`w` 用于前进。可用 `objective_key` 在目标航点触发明确的交互。纯到达目标可以省略该键。接取后直接变为可交付的任务可以省略目标路线。
- 在游戏里执行 `/wagent quest track 12345`。每个计划最多跟踪 8 个任务。重载会清除当前跟踪和操作状态。
- 接取、目标执行和交付阶段开始前，由本地 StartLux 选择继续或等待。路线跟随、战斗按键与进度核对使用现有脚本。主 App 运行前应先启动本地模型服务。
- 在主 App 中先运行 `run --module quest --quest-plan /path/to/plan.yaml --dry-run --max-duration 45`。干跑记录拟执行的步骤，需要手工推进才能看到后续阶段。实机执行前在键鼠 App 中启用会话，省略 `--dry-run`，启动后在 12 秒内回到游戏前台。可以用 `--quest-kinds campaign mainline` 只允许战役与主线候选。

## 自动场景镜头（0.2.61）

安装插件后 `/reload`，重新启动主控任务。先在开阔地停稳、下马脱战，把镜头调整为能看清脚下和前路的约 20° 浅俯视，在任务寻路页点击“将当前视角存到 5”。新保存基准后启用安全地面的有限场景俯仰；未保存仍能自动调整距离，但角度未校准。

主控自动协调跑图、坐骑、室内、搜索、交互、远近战、飞行和跑尸的取景。战斗/空中仅调整距离，关键飞行输入和交互优先。手动调整前可点“暂停/恢复自动镜头”，手工恢复用“恢复任务视角”；F8 的按住/释放由主控管理。常规镜头切换不依赖 StartLux。

0.2.62 在镜头调整开始时自动设置并核对最大距离倍率 `2.6`，再实际拉远：室外跑图/坐骑/搜索/远程战斗/飞行/跑尸为 39 码，近战 34，交互/进近 32，室内 24。旧保存视角的近距离不会再覆盖这些目标；保存角度基准仍有效。更新插件后需 `/reload` 并重启主控，以配合新的 8 秒调整预算。状态面板显示当前缩放、目标距离及上限倍率；实际画面仍待实测。

`quest_camera_requested`、`quest_camera_result` 记录请求与距离回执，`quest_camera_evidence` 记录地面调整前后截图路径；距离确认不代表画面验收。旧插件仍沿用旧恢复协议。完整配置、边界和待实测项见[镜头方案](camera-adjustment-plan.md#0261-实现对照)。

## NPC 接近受阻的视觉恢复（2026-11-15 主控更新）

NPC 接近阶段已接入现有本地 Qwen 多视角绕障。短暂下落先松开前进，等两帧地面状态；无位移、多次接近仍不到范围也会触发观察。只有转到候选方向、重新拍照确认可走后才短步，绕行成功后继续原 NPC 路线。模型输出未知或阻挡不会授权移动。已准备轮次在该任务恢复耗尽后挂起并继续其它任务。

本次仅更新 Python 主控，无需重新安装插件或 `/reload`；结束旧任务进程后重新启动。`quest_npc_approach_state` 记录具体异常状态，`quest_npc_visual_probe` 表示进入视觉流程，`quest_npc_visual_result` 表示绕行结果。键位未核对、持续未落地、失焦或数据失联仍会停止。已有截图的真实本地模型输出保存在 `data/logs/npc-obstacle-20261115-vision.json`，实机自动绕行尚待验证。

14:25 会话暴露了后续缺口：视觉选中一个候选后，复核/短步失败就直接挂起，没有尝试其它方向。第二次修复会排除失败方向，先核对剩余候选，再补看左右后方与背后；每次探路总预算 120 秒。多个可走候选才按需启动 StartLux，启动最多等 15 秒且不阻塞主控安全检查；服务失败记录原因，任务结束仅关闭本次启动的服务。低置信度只能推动原地观察，不能直接移动。

`data/terrain/` 保存每次提交模型的图片与 `report.json`，包括采样位置、朝向、序列、解析失败原文和完整模型决策。`quest_terrain_confirmation` 记录复核判断，`quest_terrain_step_result` 记录实际位移，`quest_terrain_candidate_rejected` 记录候选淘汰原因。第二次修复的模拟回归为 225 项 Python 与 6 个 Lua 脚本通过；本机离线模型重放见 `data/terrain/replay-20261115-1425/report.json`，尚未证明实机绕障交付成功。

2026-11-16 增加先退开再找路：普通旅行和 NPC 接近进入视觉恢复时，先观察后方，确认可走后转回原朝向，用 S 分段后退，目标约 4 码。每段松键等位置回执，最多四段；后退无位移就停止退避，从当前位置继续观察，后方不明则不后退。退避后丢弃旧视角、重算目标方向再找路，不会直接重走原失败方向。新增 `quest_terrain_retreat_*` 日志与后方截图；仅修改 Python 主控，重启任务生效，无需 `/reload`，实机效果待验收。

## 尸体方向导航

灵魂状态优先读取游戏的尸体坐标；缺少坐标时识别小地图墓碑或红色边缘箭头。墓碑提供地图位置，箭头只提供方向：连续两帧方向一致后沿该方向设置最多 12 码的临时路点，持续观察并分段推进。出现墓碑后转为位置导航，复活弹窗出现后停步确认。此流程使用本地 OpenCV 和脚本，不调用模型逐帧控制。

日志 `quest_recovery_minimap_arrow` 表示方向核对成功，`quest_recovery_route` 的 `source=minimap_arrow` 表示开始分段导航；`quest_recovery_minimap_missing` 表示未核对到唯一标记。截图识别和模拟回归通过不代表实机移动或复活成功。此 Python 更新下次启动主控生效，已加载 0.2.45 插件并输出小地图几何的客户端无需再次重载。

## 计数击杀任务

0.2.46 增加战后批量拾回及区域巡查。准备任务时同时核对 L（原拾回）和 O（清除旧目标后拾回附近掉落）；收到新的拾取槽清空事件后才继续下一次，最多 6 次，单次无反馈等待 8 秒后结束检查。批量期间暂停寻怪、上马和交任务。没有新反馈只表示本次未确认更多掉落，不保证附近所有尸体都已拾完。

寻怪优先用原生 QuestPOI 的范围命中查询筛选巡查点，保留已访问点并从当前位置就近推进；查询不可用时使用 90 码内的有界降级搜索。原生范围查询参照[客户端 QuestBlobDataProvider](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_SharedMapDataProviders/QuestBlobDataProvider.lua)，使用独立透明查询帧，不移动鼠标、不打开世界地图。采样间距 30 码，窗口横纵 240 码，最多访问 32 个点；此边界不是整个世界地图或完整任务区域的覆盖承诺。范围查询与批量拾回已完成代码和模拟回归，仍需实机确认。

在任务条目中用 `combat_targets` 列出可攻击的 NPC ID，并把 `objective` 的最后一个航点设为可以选中目标的位置。击杀任务使用 `combat_targets` 字段，对象交互任务使用 `objective_key` 字段。

- 游戏里把 `Tab` 绑定为选取最近敌人。在主动作栏绑定一键辅助或已生成的单技能宏，用 `/wagent combat arm 4 assist` 或 `/wagent combat arm 4 <技能ID>` 核对绑定。战斗键必须与计划中的对话和交互键分开。
- 到达目标点后，脚本在脱战时尝试选敌，只有确认目标 ID 在白名单且动作栏绑定有效时才输出。目标死亡或离开选中后，脚本等任务计数增加再继续。任务可交付时先等角色脱战，然后走交付路线。
- 如果缺少路线数据，可以在主 App 运行 `probe-quests --waypoints --duration 30`，走到任务接取点、战斗点和交付点并记录 `map=` 与 `waypoint=` 输出。开放世界的短距离地面路线需实测。当前实现会在目标点附近选敌，超出攻击范围或色条读不到目标时会停。

任务 `90882`「若是那豺狼来了」的可计数目标包括 `244669` 至 `244672`。配置时应按角色所在阵营和场景记录实际航点。[任务目标和 NPC 链接](https://www.wowhead.com/cn/quest=90882)

## 运行证据与长期推进（0.2.63）

长期开发和逐阶段实测见 [推进清单](quest-roadmap.md)。任务启动时自动建立 `data/runs/<run_id>/`，包含代码/插件/模型配置指纹、事件 JSONL 和挂起/退出摘要。日志、数据库、截图引用及模型报告使用相同运行编号。

`quest_addon_loaded` 的 `build=263` 才表示游戏回报了新版运行构建；磁盘文件一致不能替代 `/reload`。旧插件仍可读取，缺失的运行构建保持未知。摘要的 `sampled_activity_seconds` 是按观测估计的活动耗时，采样缺口单列 `unobserved_seconds`，不能当作精确输入计时。`unclassified_wait` 是待排查项，不能据此宣称已解释全部停顿。

离线重放：`.venv/bin/python -m bot.data.evidence data/runs/<run_id>/events.jsonl`。旧格式日志也可重放；没有截图的历史事件不推断具体视觉原因。本次不改变自动任务启动方式。

## NPC 自动接近与 Grail 缓存

任务脚本在缺少静态 NPC 配置时，会按当前地图和接取或交付阶段查本地 Grail 缓存。同地图仅有一个符合条件、与游戏图钉足够近的点位时，脚本可用它缩短最后一段步行。缺少缓存或存在多个点位时使用游戏图钉。角色停稳、核对活着的友方候选、选中 GUID 和 5 码回执后再互动。对话任务 ID 和阶段不匹配时关闭对话并排除该候选，再搜索其他 NPC。

## Grail 静态数据维护命令

将游戏任务导航准备好后，运行 `.venv/bin/python -m bot.cli grail-sync --tracked`。命令用两帧同一任务、地图和阶段的寻路色条识别当前追踪任务，按固定 Grail 快照补当前地图的数据。也可用 `--quest 90898` 指定任务，重复 `--quest` 可批量处理。加 `--report` 只查看可补字段。

补数目前适用于插件数据表的地图 2451，需要本地项目环境的 `lupa.lua51` 校验合并结果。接取和交付关联可以分别补齐，保留已有 NPC、点位、前置与任务行为配置。多 NPC、多出生点或缺少同地图点位时留给实时图钉与对话确认。写入有变化时同步更新插件版本和运行 build。显式加 `--deploy` 才部署到游戏目录，游戏内重载后应核对 `quest_addon_loaded`。
