# WowAgent 全场景视角调整与恢复方案

更新：2026-11-16。**0.2.62 将最大距离上限与场景拉远接入自动调整，待实机验收**。下文保留此前设计与实现记录；新版距离及预算以本节为准，模拟回归不能替代实机效果。

## 0.2.62 最大距离接入

- 每次获准开始镜头事务时读取 `cameraDistanceMaxZoomFactor`，必要时通过 `C_CVar.SetCVar` 设置为 `2.6` 并读回。首次修改前的可读原值保存到 `WowAgentDB.questCameraOriginalMaxFactor`。不会因插件加载、暂停或过期请求修改设置；不改 FOV。
- 室外步行、地面坐骑、搜索、远程战斗、飞行及跑尸目标为 39 码；近战 34、交互与进近观察 32、室内 24。游泳/载具/剧情继续让权。实际最大距离仍受客户端及遮挡限制，不能绕过墙面碰撞。
- 已保存槽 5 保留为角度基准，旧配置的 20 码等距离不会再压低室外目标。恢复槽位后再实际拉远，只有距离两次稳定且上限倍率读回正确才报告成功；设置失败、被其他插件改回或缩放不动报告受限。
- 为覆盖第一人称到 39 码，每次仍分步最多调整 3 码，最多 14 次；插件预算 8 秒，主控租用预算 8.6 秒。空中和战斗仍后台执行；失焦、释放 F8、状态失效立即取消，不等满预算。
- **待实测**：国服当前客户端的 CVar 写入/读回、39 码视野覆盖及观察细节、室内碰撞、近战与 NPC 交互取景。距离回执不等于画面无遮挡。

## 0.2.61 实现对照

以下为历史实现，距离配置和事务预算已被上方 0.2.62 替代。

- 已接入任务主循环、战斗前准备/战斗期间、旅行巡航、落地恢复和跑尸恢复。插件按公开状态报告步行、地面坐骑、室内窄道、搜索、交互、远程、近战、飞行、进近观察、跑尸、游泳及游戏接管场景；主控控制输入时机、稳定等待和失败预算。
- 距离以已保存地面值为基准，未保存默认 20；旧版数值配置的基准最低 18，避免旧近镜头成为永久目标。坐骑 +4、室内 -6、搜索 +3、交互 -2、远程 +6、近战 +4、飞行 +8、进近 +4，限制在 10–39。实际引擎上限或遮挡导致不收敛会报告受限。
- 新保存基准后，安全地面先恢复槽 5，再按场景增加 0–3 个有限俯仰步，每步沿用约 6° 的估算；旧配置仅恢复槽位与距离，不自动启用相对俯仰。未保存时仍用槽 2，不能保证约 20°。第一次测试应在开阔地调好画面后点击“将当前视角存到 5”。
- 战斗、空中和鬼魂只调整缩放，不调用 `SetView` 或相对俯仰。飞行控制的技能、转向和下降输入优先；起飞、降落操控、交互、拾取和施法窗口取消或推迟镜头事务。近地慢速的“进近观察”是距离/速度启发式场景，不充当着地证据。
- 普通切换先稳定 0.6 秒，成功后冷却 2 秒，失败冷却 5 秒；每个事务最多五次缩放，每次不超过 3，插件总预算 4 秒，主控回执预算 4.6 秒。相同受限状态不自动无限重试；输入优先级中断允许一次延期重试。这是对设计初稿“三步、三秒”的修订，使常见近镜头能在一次有界事务内拉开。
- F8 由主控按住到事务结束；松开即取消。插件同时检查场景、观察时效、危险状态和本地看门狗。手工恢复使用面板按钮，不要求玩家自己长按 F8。右键观察或可检测的外部 Lua 缩放会暂停自动镜头；面板提供显式暂停/恢复。原生滚轮、左键观察和外部插件的所有变更来源尚不能保证完整检测。
- 每次距离结果记录请求号、场景、缩放、槽位、校准标志和结果。地面调整前后保存游戏窗口截图，日志为 `quest_camera_evidence`；`composition_verified` 始终为 false，等待画面验收，未接入自动视觉质量判定。常规流程不等待模型。
- **仍有边界**：室外桥梁/悬崖/狭窄障碍没有单独的自动视觉分类，继续服从现有通路证据和地形恢复；室内标志只是窄道配置的保守入口。游泳、载具和剧情让权给游戏。团本、大秘境目前沿用职业战斗取景，不包含机制专用镜头。空中自动俯仰、视觉闭环和上述特殊场景需另做能力验证，未标为已实现。

## 目标与依据

目标是让任务全过程保持可观察的角色脚下、当前目标及下一段通路；按场景平缓调整，临时观察后恢复合适的视角。参照已学习录像的取景方式，不承诺不同地形、分辨率、角色和坐骑下逐像素复现。

- **用户要求**：地面任务常用角色后方约 20° 浅俯视；距离足够远；不频繁高速甩镜头；覆盖跑图、远程、近战、飞行等场景。
- **截图证据**：本次门口截图中围栏、任务问号、角色/宠物及界面占据较多观察区域，脚下和进门通路不清晰。单图无法确定实际缩放、绝对俯角或是否发生镜头碰撞。
- **已有实机反馈**：曾发生计时流程结束但镜头垂直俯视，以及恢复预设后视角偏平。不能以计时结束或槽位回报认定画面合格。
- **代码现状**：`QuestCamera.lua` 使用槽 5 保存玩家预设、槽 2 作为缺省；恢复检查槽位，仅缺省分支尝试补到缩放 12。Python 接收过近标志和单比特回执，没有实际缩放与失败类型。飞行、战斗等场景会推迟恢复。相对俯仰目前是手动微调。

现有规则及录像时间点见 [移动与视角](../skills/wow-playbook/references/navigation.md) 和 [战斗站位与选敌](../skills/wow-playbook/references/combat-positioning.md)。本方案的数字是调参起点，不是从录像测出的值。

## 一、分别控制距离、俯角、观察方向与 FOV

| 项目 | 方案 | 验证依据 |
| --- | --- | --- |
| 镜头距离 | 读取 `GetCameraZoom()`，分步调用相对缩放，等待稳定再复核 | 公开有效读数、缩放变化、实际画面；读数不单独证明无遮挡 |
| 镜头俯角 | 已校准原生预设为基准；临时改变使用有限相对动作 | 预设回报、稳定截图、脚下/通路可见性；时间乘速度只是估算 |
| 水平观察方向 | 后方跟随为常态；需要侧看时执行有界观察，再恢复 | 角色朝向与镜头方向分别记录；角色朝向不能充当镜头朝向 |
| 视场角 FOV | 首轮保持玩家现值；校准时记录数值、窗口比例和 UI 缩放 | 缩放拉远与 FOV 扩大分别验收，避免同时改动导致归因困难 |
| 跟随、动态俯仰、偏肩 | 先读取并记录，识别其他镜头插件及配置影响 | 不周期性覆盖用户设置；发现冲突暂停自动校准 |

公开世界镜头绝对 pitch/yaw 的可靠读写入口尚未核实，因此不能实现“设置绝对 20° 并由 API 确认角度”。采用预设恢复与画面验收。`GetCameraFOVDefaults()` 给出 FOV 默认值和玩家范围；`GetUICameraInfo()` 是 UI 镜头信息，不作为世界镜头位置。依据：[同构建暴雪生成定义](https://raw.githubusercontent.com/Gethe/wow-ui-source/297d7aa/Interface/AddOns/Blizzard_APIDocumentationGenerated/CameraDocumentation.lua)。

相对缩放和平滑旋转可参考 [LibCamera 作者文档](https://github.com/Mpstark/LibCamera)，其动画回调及角度估算也不能代替画面验证。不因第三方库提供 `Pitch` 就认为有绝对俯角回执。具体接口与安全上下文继续按 [项目 API 核对记录](retail-addon-api.md#世界镜头-api) 验证。

## 二、基准校准与配置保存

1. 在开阔、安全、平坦地面，下马脱战，停稳。确认脚下不被动作条遮住，前方路面与两侧边界清晰。
2. 保留现有 FOV、窗口尺寸和 UI 配置。以缩放 18–22、约 20° 浅俯视为地面校准起点，按画面调整。这里的缩放使用 `GetCameraZoom()` 返回尺度，通常按码理解，不是战斗射程。
3. 保存当前已确认的地面视角到项目现用槽 5，并记录角色、缩放、客户端构建、窗口比例、CVar 快照和样例画面。历史仅有 zoom 的配置迁移为“未做画面验收”，不能自动宣称合格。
4. 在同一基准上校准远程、近战、飞行观察和降落观察的相对变化。方向和响应速度必须在当前客户端实测；不沿用未经确认的鼠标像素与角度换算。
5. 首轮只使用已有槽 5，不自动占用或重置其他原生视角槽。其他场景先保存配置与样例，使用从已知基准开始的有限变化；后续如使用额外槽位，要明确分配与备份方式。
6. 临时微调不能在未知角度上反复累加。方向、基准或前次动作结果未知时停止相对俯仰，在安全窗口恢复基准。无法安全恢复的空中/战斗场景保留当前可用视角，等待合适窗口。
7. 玩家手动调整时暂停自动镜头，保留玩家新画面。只有显式“保存为基准”才覆盖持久配置；用户恢复自动控制后重新核对场景，不强行抢回旧镜头。

校准用画面条件：角色脚下可辨、场景目标或行进方向可辨、至少一条下一步通路可辨。姓名板或任务标记单独可见不足以通过。不能因为坡面没有水平地平线就误判镜头失败。

## 三、各场景的取景与恢复

下表均为**待实测的配置起点**。角度按相对水平线向下观察的视觉意图描述，不是 API 可以精确设定的读数。距离受客户端允许上限、墙面、模型及可识别性约束；到达上限仍看不清要换观察点，不无限拉远。

| 场景 | 距离 / 俯角起点 | 必须保留的画面 | 调整与退出规则 |
| --- | --- | --- | --- |
| 室外步行任务 | 18–22 / 约 20° | 脚下、前方路面、下一个路口或地标 | 后方跟随；直路维持，转弯后稳定观察，不因每次小纠偏重置 |
| 地面坐骑长途 | 22–28 / 20–30° | 坐骑前方更长路段、两侧障碍 | 上马后等模型和缩放稳定；进窄道切窄道配置，下马后核对步行配置 |
| 门洞、洞穴、楼梯 | 10–16 / 25–40° | 脚下、门框/台阶及前方出口 | 入口前减速；允许适当缩近，坡度服从通路可见性；离开障碍后再恢复，不能一被挤近就反复拉远 |
| 桥梁、悬崖、窄路 | 16–22 / 30–45° | 两侧边界和下一处落脚点 | 稳定朝前，禁止为看清而盲目横移或后退；离开边缘恢复地面预设 |
| 搜索 NPC、怪、物件 | 20–26 / 20–35° | 候选分布及通向候选的路面 | 先宽视野找候选，再同侧小幅观察；候选确认后停镜头，旧屏幕坐标失效 |
| 交互、拾取、交付 | 14–20 / 25–35° | 目标/物件、脚下和实际接近通路 | 已清楚则无需调整；悬停核对、点击和对话期间锁住镜头；结束后按下一任务场景决定是否恢复 |
| 远程任务战斗 | 22–28 / 25–35° | 自己脚下、主目标、侧向躲避路线 | 到有效射程停步输出；开战前准备，战中只修影响观察的遮挡，不逐次施法或切敌重置 |
| 近战任务战斗 | 20–26 / 35–45° | 自己脚下、目标朝向、怪群外沿 | 进近前准备；大模型遮挡时有限拉远/侧看；角色面对目标另行确认，不能靠镜头回正修正攻击朝向 |
| 团本、大秘境战斗 | 24–32 / 30–45°，空间允许时 | 机制区域、队伍位置、脚下及目标 | 远程/近战作为基础配置，按具体场地覆盖；窄房间优先局部可见性，不能为了全景丢掉脚下；当前仅设计取景，不代表已具备副本执行能力 |
| 平稳飞行巡航 | 24–30 / 10–20° | 飞行方向、山脊/树冠/建筑及净空 | 起飞前准备；平稳航段才允许已验证的纯观察动作；不因看地面擅自改变飞行方向 |
| 驭空术巡航 | 26–32 / 10–20° | 更远的前向障碍与可绕行空间 | 起飞、升空、冲刺、急转由飞行控制独占输入，镜头不插入；安全直航仍需验证观察输入不改变机头 |
| 进近与降落观察 | 20–28 / 35–50° | 预定落点、落点前缘及周围障碍 | 先由飞行控制减速，再安排短暂俯看；观察俯角与实际下降动作分开；确认着地、停稳后才恢复地面配置 |
| 游泳、水下通道 | 14–22 / 随通道调整 | 水面/出口或上下方障碍、目标层 | 不套用地面俯角；水下输入可能控制游动方向，未经验证不自动俯仰；出水后重判地面/飞行状态 |
| 跑尸与复活 | 跑尸 18–22 / 20–30° | 前路与地形边界；复活时保持按钮稳定 | 先允许已核验的灵魂场景控制；弹窗出现即停止镜头；确认存活和地面稳定后恢复基准，再接原任务 |
| 载具、交通工具、剧情镜头 | 使用游戏镜头或专用配置 | 当前控制席需要的目标/路线 | 默认交给游戏，取消通用镜头动作；退出后确认动作栏、移动状态和角色控制权，再恢复对应配置 |

场景选择不能只靠“距离任务点几码”：结合移动模式、任务阶段、已核验专精/输出方式、战斗状态、地图层及场景证据。普通自动攻击射程不等于当前职业的站位方式；兽王与生存分别配置。室内外标志不足以证明眼前是否有墙或顶棚。

## 四、统一控制器与切换规则

新增单一镜头协调器，导航、战斗、飞行、拾取只提交场景请求，不能各自直接抢镜头。动作仍走现有插件入口和获准键鼠助手。

优先顺序：

1. 急停、失焦、输入会话失效、数据失联：停止镜头动作并走现有会话释放流程。
2. 玩家手动接管、剧情或载具专用镜头：取消自动镜头，等待明确恢复控制。
3. 关键操控锁：躲避、飞行方向调整、施法操作、悬停点击、复活确认；镜头等待安全窗口。
4. 当前移动/战斗模式确定基础配置，窄道和遮挡只在该模式允许范围内覆盖。
5. 搜索等临时观察结束后，重新从最新状态计算目标配置，不盲目恢复过期场景。例如搜索中入战应切战斗，而不是恢复跑图。

非紧急场景连续稳定约 0.6 秒才提交切换，切换后至少保持 2 秒；相似场景且画面合格不切。入战、失焦等安全事件立即处理。一次只运行一个缩放/旋转事务，紧急事件使旧事务及其延迟回调失效。

地面镜头校准可以先停步；空中不能套用“释放所有移动键再调镜头”，应由飞行控制决定可用窗口。战斗中也不能因为视角不够漂亮而打断必要输出、打断技能或躲避。

所有 `MoveView*Start` 配对 `Stop`，插件本地看门狗与主控超时双重约束；退出、状态切换及异常分支都取消自己持有的镜头动作。只释放自己拥有的输入，急停才调用会话全量释放。

## 五、调整事务与反馈闭环

事务流程：选择配置 → 检查前置条件 → 有限调整 → 等稳定 → 核对读数/画面 → 完成、降级或退出。

- 每次请求带请求编号、场景、原因、期限及输入所有者。新请求取消旧请求；旧定时回调不能覆盖新场景。
- 读取实际缩放、槽位、数据序列与时效；不可读保持未知，不转换为 0 或成功。
- 缩放单步初始上限 3 个单位，观察间隔至少 0.35 秒；距离误差允许约 1 个单位，至少两个不同新序列且相隔 0.3 秒的稳定读数才标记“距离确认”。参数配置化。
- 一轮普通调整最多 3 步、总预算 3 秒；同场景失败至少冷却 5 秒。预算耗尽返回明确结果，不立刻开启同样的一轮。很大的初始偏差留到安全校准处理，不依赖高频无限拉远。
- 俯仰一次只做已标定的小步，开始、结束和取消都可追踪；缺少已知基准或画面验证时不自动连续微调。
- 视觉校验放在首次校准、显著切换、异常遮挡和恢复失败时；日常稳定运行复用有时效的配置验证，不每个周期等待模型。
- 画面采集后若角色移动、镜头变化、场景/目标变更，拒绝用于点击或通路推断；镜头稳定后重新获得目标屏幕坐标并悬停核对。
- 视觉模型未返回或置信不足时只能记“距离确认，取景未知”。当前路径有有效独立证据可有限继续；依赖未知画面的移动或点击必须等重新观察。不能把镜头等待计为地形卡住。

反馈至少区分：`requested`、`view_reported`、`distance_verified`、`composition_verified`、`limited_or_obstructed`、`unknown`、`interrupted`、`timed_out`。`view_reported` 仍保留其原义，不升级为画面成功。

## 六、异常诊断与恢复顺序

| 现象 | 先核对 | 有限恢复与退出 |
| --- | --- | --- |
| 距离太近，周围开阔 | 缩放新读数、当前配置、动画是否稳定 | 最多一轮分步拉远，确认变化；没有变化不继续同样发键 |
| 距离数值正常，画面仍被遮 | 墙/树/大模型、视角方向、UI 遮挡 | 进行一次有依据的侧看或安全位置调整；不把缩放正常当成功 |
| 拉远后仍靠近墙体 | 墙面证据、刚走过的安全位置 | 标记受限，进入窄道配置；有安全通路才退回/侧移；不能盲目后退 |
| 俯角过平或垂直 | 当前是否安全地面、基准是否通过验收 | 安全时恢复一次基准，再检查画面；基准本身不合格则请求校准，禁止向角度极限持续推动 |
| 落地后距离或方向异常 | 两帧着地、移动/坐骑状态和输入归属 | 按顺序结束飞行、确认下马、恢复地面镜头，再精确接近；镜头正常不代表下马成功 |
| 方向与前进不一致 | 角色朝向、刚才是否仅观察镜头 | 恢复后方观察，下一步前核对真实移动方向；不把画面左右直接当世界左右 |
| 画面持续被动作条、追踪器占据 | 可观察区域、窗口和 UI 缩放是否变化 | 报告 UI 遮挡，需要单独布局调整；镜头不能解决所有 UI 占屏，本轮不自动隐藏界面 |
| 外部插件反复改镜头 | 设置变化、动作无请求却反复变化 | 暂停自动镜头并记录冲突，保留用户配置；不互相覆盖重试 |
| 无回执、旧序列、受限读数 | 插件版本、协议、前台/输入会话 | 停止对应调整，记录未知/超时；若数据链整体失联按现有安全停止处理 |

恢复后的最终配置由当前场景决定：出洞恢复跑图，战后先处理拾取，拾取后再恢复旅行，降落先确认地面状态，复活后先核对角色控制权。单纯镜头距离未达偏好不挂起整个任务；无法观察到必要通路且恢复耗尽时，归为局部路径/观察能力问题，按任务挂起机制处理。飞行或战斗中失去必要观察能力要走各自已验证的安全处置，不能仅挂起任务后继续原输入。

## 八、实施顺序

1. **先修距离与反馈**：地面恢复对已保存预设也校验实际缩放，加入明确成功/失败和超时，保留旧协议。用本次门口画面作为遮挡失败样例，不用单图推算精确角度。
2. **建立地面场景协调**：跑图、坐骑、窄道、搜索、交互及落地恢复；先解决现在的近镜头问题和反复恢复问题。
3. **接入远程与近战**：兽王、生存分别校准，优先开战前准备、战中最小修正、战后恢复；验证不会改变目标或打断必须执行的动作。
4. **接入飞行与特殊状态**：起飞前准备、巡航观察、降落及复活；驭空术观察与航向严格互斥。游泳、载具、剧情先提供明确让权和恢复，专用自动调整在控制语义验证后启用。
5. **完善画面校验与参数**：实机场景前后对比，按证据调整阈值；再考虑 FOV 或 UI 布局优化，不把这些额外改动混入第一轮效果判断。

## 九、验收与留证

离线回归重点：保存槽正确但距离错误、缩放受限、读数正常但画面遮挡、旧格式兼容、过期/回绕回执、超时后旧回调、场景抖动、手动接管、镜头变化后旧点击坐标失效、入战/失焦/急停取消、镜头等待不触发卡住、落地/复活继续原任务。测试运行全量 Python 与现有 Lua；新增行为测试不把模拟结果写成实机成功。

| 实机场景 | 核心验收点 |
| --- | --- |
| 开阔地故意拉近再恢复 | 距离有实际变化、两帧稳定、脚下和前路清楚，且无无效重复 |
| 门口、墙角、洞穴/楼梯 | 不反复顶墙拉镜头；离开后恢复；对边缘未知地面不盲走 |
| 坐骑 → 步行 → NPC 交互 → 续跑 | 无场景来回跳；镜头不打断悬停/点击；反馈关联本次事务 |
| 兽王远程与生存近战 | 保留脚下和目标、目标身份不因镜头改变；朝向/射程由战斗反馈单独确认 |
| 平稳飞行与驭空术 | 观察不造成意外转向/下降；起飞、加速和减速不被镜头抢输入 |
| 进近 → 着地 → 下马 → 恢复 | 每一步有独立反馈；恢复不会抢在实际着地前发生 |
| 跑尸 → 复活 → 职业准备 → 续跑 | 弹窗稳定、实际存活后正确恢复、保持原任务上下文 |
| 手动镜头、切前台、急停、重载 | 自动控制停止且无遗留旋转；重新启动重新核对，不执行过期请求 |
| 载具/剧情、水下、多人副本 | 分别留证；未测通过的自动调整保持未启用，不能由野外任务验收代替 |

每个样例记录：构建/主控版本、地图、角色和专精、场景、窗口尺寸及 FOV、缩放前后值、动作与反馈时间、失败原因、前后截图。画面验收看必要区域可见性与舒适度，不用单张图宣布精确俯角。首轮完成普通调整应在 3 秒预算内得到明确结果；阻挡和数据缺失必须明确失败或降级，不以耗尽时间伪装成功。
