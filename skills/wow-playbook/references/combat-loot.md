# 战斗与拾取

## 找怪与攻击

- 宽视野的第三人称镜头优先，保留玩家可用的俯角；靠近平视/俯视的具体角度由场景验证，不固定为截图的像素坐标。
- Tab 搜索前检查当前可见目标。采用同方向的小幅平缓转动、短暂停稳、再 Tab；完成当前扇区后再换向，避免快速左右交替。有限扇区无目标后移动到新的可观察点。
- 找不到怪时仍保留战斗目标搜索，按已有地图依据做有限局部换点；搜索预算耗尽明确停止。不要转入鼠标盲扫物件，也不要猜测任务类型变成采集。
- 选中目标后核对其是否与任务或当前自卫有关；有可靠身份时锁定同一目标，避免每次攻击前 Tab 换怪。同 NPC ID 的两个个体不是同一目标，使用已有 GUID/目标 epoch 关联。
- 攻击需要在该技能的有效距离内、朝向正确且无遮挡。优先读取可公开的技能/动作栏射程和游戏错误反馈；距离未知不当成已在范围。
- 超出射程时先朝向目标，短步接近并逐次检查，进入范围立即停止前进。显示“目标在背后”时暂停输出、平缓修正角色朝向；持续视线遮挡应绕障，不靠反复施法解决。
- 任务途中被攻击时进入自卫，结束后恢复原任务阶段。目标瞬间从读数中消失时给出有限的状态同步等待，不立刻另选怪；死亡、脱战和任务进度更新可能分帧到达。

## 尸体与宠物拾回

角色复活后的准备独立于战斗拾取。优先找回仍存活的宠物并令其跟随。确认宠物死亡时先复活，未发现宠物时先召唤，猎人在召唤无反馈后可尝试复活一次。按游戏状态确认宠物已存活，再补缺失的职业 Buff。当前支持猎人和术士宠物，以及法师、牧师、德鲁伊和战士的常驻 Buff，也允许为角色配置已学会的召唤技能和 Buff。已有 Buff 时跳过，确认准备完成后才恢复原任务。此流程已通过模拟测试，待实机验证。

1. 保存实际攻击过的目标身份、死亡/丢失时间、任务基准进度。目标丢失后仅在已核对绑定且条件适合时使用 P 恢复上一个目标，再确认身份；不要无限按 P。
2. 猎人拾回仅在已经学会、宠物存在且存活、L 临时绑定及宏内容核对、角色处于允许状态时使用。其他职业不强行走此分支。
3. **实测纠错：`corpse_lootable=False` 不能单独禁止拾回。** 当前日志显示目标已死、`fetch_ready=True`、`lootable=False`，脚本未按 L；用户手动按 L 成功。允许对刚结束的已确认战斗执行一次有界拾回尝试。目标无关或仍活着时不能套用该例外。
4. 按 L 后等待宠物往返和结果，不立刻换怪/上马。当前实现单次等待最多 8 秒；这只是当前预算，后续按实测路径长度优化，不能理解为技能保证耗时。
5. 任务进度增长可确认任务物品获得。同一尸体从明确可拾取变为不可拾取可作为尸体被清空的证据，但不能断言是我们的施法造成；仍需核对任务进度。按键前后的 `False → False` 不算成功，也不能直接报告“技能施放失败”。
6. 拾回无确认反馈后，若同一尸体与互动范围已确认，可回退到靠近再 F 拾取；移动采用短步、朝向和避障反馈。信息不足时保留失败原因，不能宣称拾完。无任务掉落的击杀需要结合任务/敌人证据判别，不能默认每只怪必掉任务物品。

## 任务物件（南瓜等）

- 分开“发现物件”“走到附近”“鼠标确认”“点击”“获得物品/进度”五个状态。
- 大地图/小地图负责引导，世界画面确认具体物体。远处看得见不代表可互动；短步接近，必要时下马、修正朝向和镜头。
- **用户要求：彻底取消鼠标盲找降级。** 不使用规则网格、随机点、无目标的全屏悬停。只处理视觉识别候选或游戏已报告的任务物件鼠标位置。截图失败、识别为空或仅有地图坐标都不能启用盲扫。
- 当前每次最多核对 6 个有依据的候选，悬停后至少等待 0.5 秒和新状态；仍要由游戏提示确认，颜色识别本身不代表任务物件。没有候选时返回 `quest_object_visual_target_required`；通用未知物件缺少屏幕定位时需要补充识别能力，而不是恢复盲扫。
- 悬停后核对提示/目标类型及鼠标实际位置，再发送实际右键按下与释放；不能只移动鼠标就当成点击。多屏截图和点击统一坐标，窗口移动后重新标定。
- 点击后停止继续扫描和移动鼠标，等待拾取/交互及任务反馈；失败时区分距离、遮挡、点错对象、键鼠事件未到达、背包或任务条件问题，再有限重试。
- 已验证的世界物件输入入口是 `click_world_object()`，保持它的原生输入语义；不要退回曾经只有悬停效果的普通路径而不实测。
