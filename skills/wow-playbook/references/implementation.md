# 实现与验证

## 架构与入口

以下路径相对 WowAgent 仓库根目录：

| 职责 | 当前入口 |
| --- | --- |
| 任务公开状态、互动宏、临时键位 | `addon/WowAgent/Quest.lua` |
| 战斗目标、技能准备和状态 | `addon/WowAgent/Combat.lua` |
| 色条解码 | `bot/perception/quest_channel.py`、`travel_channel.py`、`combat_channel.py` |
| 任务轮次、导航与拾取调度 | `bot/modules/quest.py` |
| 找怪、范围、朝向与战斗状态机 | `bot/modules/combat.py` |
| 旅行与绕障 | `bot/control/quest_travel.py`、`navigation.py`、`pathfinding.py` |
| 屏幕定位与视觉 | `bot/perception/capture.py`、`cv.py` |
| 本地键鼠 | `bot/control/input_helper.py`、`macos/KeyboardMouse.swift` |
| 主控启动 | `bot/cli.py`、`macos/Controller.swift` |

共享层负责状态时效、地图/屏幕坐标、输入、旅行、战斗、交互、恢复和日志。上层任务/采集/副本组合共享能力；某个任务的特殊规则保留在对应执行器。StartLux 选择有前置条件的动作候选，视觉模型提供观察，脚本掌握执行预算和成功判定。

## 当前键位约定

以插件“准备”后的核对结果为准，不把这张表当作游戏固有默认值。宏和临时覆盖集中在插件中配置；脱战准备、读回核对、恢复旧绑定，避免覆盖未知动作栏内容。

| 键位 | 当前项目用途 |
| --- | --- |
| W / S / 左右方向 / 空格 | 前进、后退、角色转向、跳跃/起飞 |
| Q / E | 核对后才能用于左右横移 |
| Tab / 输出键（通常 1） | 搜索敌人 / 战斗输出 |
| 5 / 6 / 7 / 8 | 飞行风格、飞行坐骑、地面坐骑、下马 |
| K / F / 9 | 选择交互目标、游戏互动、任务对话 |
| J | 已配置的任务道具；根据该道具目标条件使用 |
| L / P | 猎人拾回 / 恢复上一个目标 |

驭空术动作栏会覆盖普通动作栏，升空、急停、俯冲等需动态核对；不存在强制使用 X 的约定。普通拾取还需核对自动拾取设置。按键冲突或准备失败要准确报告失败项。

## 排错与验证

1. 先读 `data/logs/quest-session.log`；需要前后会话时查 `data/logs/bot.log`。当前会话文件会覆盖，重要失败保存关键状态与时间戳。Lua 报错检查正式服 `Logs/General.log`。
2. 串起“状态 → 决策 → 输入请求 → 反馈”。无 `quest_fetch` 说明没有走发送 L 的分支；出现该日志只代表请求，不证明施法成功。类似地，点击日志不能证明拾取。
3. 使用用户手动成功的动作作为控制样本，排查脚本额外门槛、键位、输入路径和等待时序。不要直接归因于权限或游戏拒绝而无日志证据。
4. 回归测试覆盖实际失败状态、正常成功、无反馈超时、有限重试和状态变更。运行 `.venv/bin/python -m pytest -q` 或相关模块；改 Lua 时运行 `tests/lua` 的相关 `lupa.lua51` 测试。测试是模拟验证，实机另列。
5. Python 主控下次启动从仓库载入；已有进程不会自动换代码。仅改 Python 时通常无需 `/reload`。更新游戏 Lua 后需要安装对应文件并重载；不要重复要求授权或重建无关 App。
6. 已配置的一次性会话由“授权并运行已准备任务”触发；不要把查看日志、模型决策、正常重试设计成需要聊天确认。真实权限、会话结束或准备失效时说明具体原因。

## 新规则如何落地

对新增准则记录：触发状态、所需证据、动作、等待预算、成功反馈、失败后状态与测试位置。与本 skill 冲突时以用户最新要求和实测证据修订；模型识别结论要标注置信与时效。角色受限状态、前台焦点或色条失联时沿用现有停止和释放按键机制。
