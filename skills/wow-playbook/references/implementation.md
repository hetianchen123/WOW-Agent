### 键位分配设计

**绑定注册表。** 插件集中声明每个动作的标识、首选键、实际 WoW 绑定或安全按钮、适用客户端和状态、按压方式、必需性、校验及回执类型。移动、任务、战斗、恢复、镜头和飞行模块通过同一个分配器申请键。Python 用动作标识读取插件公布的实际物理键。Swift helper 保留物理键白名单和窗口校验。三方用自动测试核对键名、代码与协议版本。用户可在面板的只读「键位检查」查看基础绑定、实际生效绑定、动作栏格内容、冲突对象及结果。

| 分配层 | 规则 |
| --- | --- |
| 原生控制 | 优先沿用能由 helper 发送且已读回的原生键。保留 W/S、转向、空格、互动、选敌及玩家现有的下降、俯冲、载具和系统键。历史首选键有冲突时展示实际动作与候选。更换玩家已有绑定须由配置明确允许。 |
| 地面任务和职业 | 保持 K、9、J、L、O、P 的现有首选。按技能、角色及任务启用。普通动作只在脱战准备时装入既有 WowAgent 格子或已确认空格。为同一配置中的附加任务和能力预留键位，从分配开始就参与冲突检查。 |
| 职业和客户端差异 | 分开正式服与无限服配置。无限服优先保留 F4 职业成长，镜头和分割标定优先使用已核对的左右键和俯视事务，通过独立图像配准确认视角。正式服的鼠标标定独立申请可用键，使用前核对租约。 |
| 可选辅助 | 镜头、补给、宠物和挂起先尝试首选键，再从 helper 支持且未保留的空键池分配。借用已有动作栏键仅限明确启用该配置、当前动作格已核对为空的场景。无可用键时显示功能级降级，避免无声覆盖。 |
| 飞行及载具 | 规划时先锁定全局预留和已核对的原生飞行键。动态分配下降、俯冲和下马，并在动作栏切换后重新校验。飞行技能取当前动作栏的技能 ID、可用性和键位。缺关键能力时按已验证的方式降级。 |
| 独立模块及急停 | 钓鱼、采集、卖货和旧 YAML 任务在各自会话内申报配置键。托管会话同一时间只允许一个执行模块。系统急停组合单独保留。helper 的菜单停止继续有效，统一全局组合键前须先证明当前权限下能够接收并立即释放。 |

**准备与动态复核。** 脱战时先只读扫描基础绑定、覆盖及动作栏，完成冲突检查后再提交临时覆盖。对整张分配表统一读回验证，必需动作失败即回滚本次覆盖并说明原因。可选动作失败只撤销该动作。通过后公布绑定代次、动作、实际键、能力及状态。切换任务、动作栏、专精、载具、世界、角色或收到绑定变化时，立即使受影响的分配失效。主控先释放受影响的键，再等当前上下文的新代次。只在确需重新写入时等脱战。战斗中给出明确的等待状态。动态动作栏可复用数字键的条件是两个上下文互斥、切换时先释放并重新读回绑定与技能。

**发送和清理。** 每次发键校验当前会话、前台、绑定代次和动作状态，输入回执与游戏动作成功分开记录。运动是持续按键或短脉冲，镜头是有截止时间的租约，职业成长、任务互动和物品使用各等自己的游戏回执。同一个键只有一个当前持有者。急停、失焦、断连、超时和任务结束立即释放物理键。插件关闭或结束轮次时清除本会话临时覆盖，战斗锁定期间先让能力失效，脱战清除。宏和动作栏内容属于单独明确的保存操作，临时键位清理不删除用户已有宏或动作。

**实施与验收顺序。** 先实现只读键位检查和跨层一致性测试，再把现有键位逐组迁移到分配器。用临时覆盖断言验证 F4 成长与镜头标定、F6 与原生下降、数字 5 在两种客户端、借用栏位被填入、飞行和载具换栏、脱战清理及失焦释放。然后分别在正式服和无限服准备实际任务，记录同一会话的绑定读回、游戏动作回执和结束后的原绑定恢复。绑定设计验收通过后再叠加采集频率、输入调度和路径跟随优化。

## 排错与验证
