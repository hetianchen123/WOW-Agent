# 任务轮次与交互

以下是用户指定的运行目标；实际支持范围以代码与实测为准。

## 一轮流程

`发现附近任务 → 接取附近全部可接任务 → 逐个完成目标 → 批量交付 → 刷新并进入下一轮`

其中任何阶段遇到当前位置可立刻交付的任务，优先交付并接取后续，再返回原阶段。不能为了“集中交付”推迟一个已经可交、可开启后续的当前 NPC 对话。

- “附近全部”指本轮发现范围内、当前角色可接且符合用户筛选的任务，不代表已证明地图上再无任务。说明扫描边界、来源与不可达候选。
- 起点可来自插件公开任务/地图标记、已有数据库或当前 NPC 对话；数据库只给候选。到 NPC 后，以实际对话列表核对全部可接/可交任务；领取一个后重新读列表，直到没有剩余符合条件的条目。
- 不要求用户预填每一个未知任务 ID；发现后按日志目标分类选择已有执行能力。任务链资料可解释前置和分支，但不能替代当前角色实际可接状态。
- 接完一个 NPC 后继续本轮其他候选，按任务 ID、NPC 身份及阶段去重，记录不可达/无任务的原因与冷却，避免反复点击同一个已经领取完的 NPC。
- 阶段和候选队列可恢复；刷新发现结果要处理解锁的新后续，不能因 NPC 已访问过就永久排除它。

## 走到 NPC 与对话

- 标记到达与互动距离分别判断。接近时朝向正确、落地、下马，短步靠近；项目要求约 5 码内再互动，实际还需游戏互动条件确认。
- 坐标不是 NPC 本身；先确认人物身份或匹配的互动目标，再使用 F。仅选中目标不表示打开了对话。
- 当前流程中 F 为游戏互动，9 推进经过任务 ID 校验的对话。核对对话阶段及任务 ID 后再操作；接取成功以任务日志出现为准，交付成功以任务状态变化为准。
- 距离不足时继续有界接近；对话未打开则检查选中对象、朝向、遮挡、临时键位及互动设置，不能只反复按 9。
- 多个奖励、特殊对话选择按已有用户配置和规则处理；缺少选择依据时给出具体待处理项，不能随机选择后宣称完成。

## 目标执行分类

| 任务目标 | 所需动作与成功反馈 |
| --- | --- |
| 击杀 | 找怪、射程和朝向确认、战斗、日志击杀计数增加 |
| 击杀掉落 | 战斗后保留尸体、拾回或普通拾取、物品/目标进度增加 |
| 采集物件 | 找到世界物体、短距接近、确认悬停、实际点击、进度增加 |
| 对话/访问 | 确认 NPC、范围、正确对话阶段、任务进度变化 |
| 专用道具 | 读取当前任务道具及使用条件；确认目标/位置后使用并核对结果 |
| 护送、载具、组合目标等 | 单独能力与阶段模型；现有流程不支持时报告缺口，不能强套击杀或拾物 |

“战役/主线/支线”是任务组织分类，“击杀/掉落/互动”是执行分类，二者分开。API 没有足够证据时保留候选/未知，不仅靠任务名称猜测。

## 验收样例

同一 NPC 两个可接任务均接完后才离开；旁边第二个 NPC 也被访问；刚接就完成的先交并接后续；已有任务不重复领取；击杀但没捡任务物品仍留在目标阶段；交付后新任务进入下一轮或即时后续处理。
