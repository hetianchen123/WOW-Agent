# 任务轮次与交互

以下是用户指定的运行目标；实际支持范围以代码与实测为准。

## 一轮流程

`发现附近任务 → 接取附近全部可接任务 → 逐个完成目标 → 批量交付 → 刷新并进入下一轮`

其中任何阶段遇到当前位置可立刻交付的任务，优先交付并接取后续，再返回原阶段。不能为了“集中交付”推迟一个已经可交、可开启后续的当前 NPC 对话。

- “附近全部”指本轮发现范围内、当前角色可接且符合用户筛选的任务，不代表已证明地图上再无任务。说明扫描边界、来源与不可达候选。
- 起点可来自插件公开任务/地图标记、已有数据库或当前 NPC 对话；数据库只给候选。到 NPC 后，以实际对话列表核对全部可接/可交任务；领取一个后重新读列表，直到没有剩余符合条件的条目。
- 不要求用户预填每一个未知任务 ID；发现后按日志目标分类选择已有执行能力。任务链资料可解释前置和分支，但不能替代当前角色实际可接状态。
- 接完一个 NPC 后继续本轮其他候选，按任务 ID、NPC 身份及阶段去重，记录不可达/无任务的原因与冷却，避免反复点击同一个已经领取完的 NPC。
- 阶段和候选队列可恢复；刷新发现结果要处理解锁的新后续，不能因 NPC 已访问过就永久排除它。
- 一轮内挂起的任务不自动无限重试；未结束轮次的重载/准备继续保留挂起。轮次已结束或没有可续项时，用户重新准备表示开始新一轮：按游戏日志对账，重试本轮所有未完成项，不能只解除选中任务的旧挂起。已交付/放弃的旧队列项移除。主控摘要须包含角色存档带入的挂起数量；只有数量回执时不得编造任务 ID 或原因。
- **实机日志（2026-11-12 17:59）**。90887 和 90886 分别在吉安娜与萨尔处交付，最后一次交付约两秒后旧版结束了轮次。现场仍有新任务标记。**代码已实现，接取待实测（0.2.50）**。对话和地图未找到接取项时，资料中有明确前置关系且前置均已被游戏判定完成的同地图附近任务，可以作为核对候选。去对应 NPC 检查任务列表，按相同任务 ID 核对接取。没有候选时再次请求地图任务数据，轮次结束前最多等六秒。模拟回归覆盖地图列表为空时 90886 交付后切换到 90888，以及地图晚于两秒返回新任务。

## 走到 NPC 与对话

- 标记到达与互动距离分别判断。接近时朝向正确、落地、下马，短步靠近；项目要求约 5 码内再互动，实际还需游戏互动条件确认。
- 坐标不是 NPC 本身；先确认人物身份或匹配的互动目标，再使用 F。仅选中目标不表示打开了对话。
- **日志证据（2026-11-12 17:05）**。90885 已交付，90887 到达标记后没有选中动作，18 秒后退出。窗口显示仍选着萨尔，任务数据的接收者是吉安娜。**代码已实现，待实测**。到标记 8 码内，软目标没有给出匹配 NPC 时，可用任务数据的本地化全名让 K 主动选中。继续用已知 NPC 编号和 5 码范围核对 F，后续按实际对话的任务 ID 逐项交付。选中失败和选中后距离不足分别诊断。
- 当前流程中 F 为游戏互动，9 推进经过任务 ID 校验的对话。核对对话阶段及任务 ID 后再操作；接取成功以任务日志出现为准，交付成功以任务状态变化为准。
- 距离不足时继续有界接近；对话未打开则检查选中对象、朝向、遮挡、临时键位及互动设置，不能只反复按 9。
- **实机日志（2026-11-15 14:10，插件 0.2.61）**：90895 交付阶段首次短步后触发 `quest_turn_in_approach_unsafe`。旧日志没有具体状态位，不能确定是下落还是键位核对失败。普通旅行的视觉绕障没有接到 NPC 接近分支，这是没有调用模型的代码原因。
- **真实截图离线模型结果（2026-11-15）**：对当次 `camera_after_interact` 截图使用运行中同样的裁剪范围，本机 Qwen3-VL 将前方判为阻挡，描述了木障碍；左右也未给出可走通路，建议继续观察。单张图不能确认绕行成功，更不能证明退出瞬间的角色状态位。
- **代码已实现，待实测（2026-11-15 主控更新）**：靠近 NPC 时短暂下落先释放前进，最多等 3 秒，两个不同序列、相隔至少 0.3 秒的安全地面样本才继续。站稳后、原地无位移或接近预算耗尽时，进入 Qwen 多视角探路；若已确认匹配 NPC 在 5 码内，则直接重新核对交互。缺少键位核对、骑乘/飞行/游泳仍停止并记录具体 flags，不以视觉替代输入安全条件。
- **代码已实现，待实测**：视觉绕行后恢复原 NPC 步行路线，不能因目标仍被选中就跳过绕行路线继续直冲。当前 NPC 阶段最多两次探路，同一个 3 码内卡点不重复探查；无模型、无可靠通路或预算耗尽时，已准备轮次按任务级挂起继续其它任务。普通单任务模式会给出具体失败原因。日志入口为 `quest_npc_approach_state`、`quest_npc_ground_stable`、`quest_npc_visual_probe`、`quest_terrain_decision`、`quest_npc_visual_result`。
- **实机纠正及代码修复，待复验（2026-11-15 14:25 会话）**：一次探路中，第一个方向复核失败不能直接挂起整项；须排除该方向，继续其他已观察候选或补看更大角度，全部候选耗尽或达到总预算才挂起。此次两项任务挂起流程生效，但没有交付，不能算任务闭环成功。详见[移动与视角](navigation.md#卡住后的升级顺序)。
- **用户要求及代码实现，待实测（2026-11-16）**：NPC 贴近障碍时的视觉恢复也先核对后方、退开约 4 码，再从新位置找路。退避期间保持原任务与 NPC 目标；不能把退避位移当作 `detoured` 成功，也不能因为 NPC 仍选中而跳过重新观察。
- 多个奖励、特殊对话选择按已有用户配置和规则处理；缺少选择依据时给出具体待处理项，不能随机选择后宣称完成。
- **代码已实现，待实测（0.2.49）**。已知 NPC 按地图、编号与本地化全名定位，附近的同名人物仍需核对编号。实际任务列表提供的发放者身份和名字可供本轮后续接取使用。找不到候选时，角色从任务标记方向开始按 30° 扇区缓慢转一圈，最多 35 秒。打开对话后优先处理列表里已在本轮队列的可交任务。误开其他 NPC 的窗口时，仅核对当前任务条目或关窗，排除当前任务已确认无匹配条目的候选，最多恢复两次。
- **代码已实现，待实测（0.2.49）**。进行中的单一目标若明确写着“与某人交谈”或对应英文，可在任务标记附近按名字选中非敌对 NPC，确认 5 码范围后互动。等待任务状态或进度变化；仍显示未知剧情选项时停在对话窗口。剧情选项需有明确配置才能进一步自动执行。
- **待验证的地形风险**。「拯救激流堡」先按已知位置到达城门区域，接收者在城墙上方。二维标记到达无法确认楼层。需要到达正确平台后再验证 NPC 身份和互动距离。[任务位置资料](https://www.wowhead.com/cn/quest=90888)

## 目标执行分类

| 任务目标 | 所需动作与成功反馈 |
| --- | --- |
| 击杀 | 找怪、射程和朝向确认、战斗、日志击杀计数增加 |
| 击杀掉落 | 战斗后保留尸体、拾回或普通拾取、物品/目标进度增加 |
| 百分比资源条 | 在任务区域搜索已核实的目标；击杀后核对百分比，需要掉落则拾取；100% 后等游戏确认可交 |
| 采集物件 | 找到世界物体、短距接近、确认悬停、实际点击、进度增加 |
| 对话/访问 | 确认 NPC、范围、正确对话阶段、任务进度变化 |
| 专用道具 | 读取当前任务道具及使用条件；确认目标/位置后使用并核对结果 |
| 多目标 | 按任务日志顺序选第一项未完成目标，按该项的类型、进度和匹配证据执行 |
| 护送、载具和特殊剧情 | 按已核对的专用流程执行。缺少流程时记录挂起原因 |

“战役/主线/支线”是任务组织分类，“击杀/掉落/互动”是执行分类，二者分开。API 没有足够证据时保留候选/未知，不仅靠任务名称猜测。

- **用户要求**：资源进度任务在小地图所示的任务区找怪，击杀并拾取任务物品，进度满后再交。
- **实机证据（2026-11-12 21:19–21:21）**：「击退围攻」90893 的任务追踪器是 68%，小地图有蓝色范围；旧色条误报 0/1，主控停在 `quest_objective_profile_required`。
- **代码已实现，待实测（0.2.53）**：从任务 API 读取百分比，优先沿游戏原生任务范围搜怪，范围不可读时只在地图标记周围 90 码有限搜索。目标由任务提示或该地图的已知任务怪名单核对。战后先走已有拾回/拾取流程；没涨进度可以换怪，连续四次无进度停止并记录。进度 100% 后等游戏确认为可交，继续原有轮次。测试覆盖从 68% 续跑、拾取后涨进度、无掉落换怪及 100% 等待可交状态。
- **代码已实现，待实测（0.2.60）**。导航色条输出当前目标序号、操作类型、计数和完成标记，切换时释放前一项目标的导航与搜索状态。整任务以可交付状态和交付回执为准。
- **代码已实现，待实测（0.2.60）**。任务级错误耗尽恢复预算后，用已核对的 F5 挂起当前 ID 和阶段，确认回执后由游戏选下一项。角色存档按游戏任务日志对账。失焦、输入会话失效、数据失联和无法恢复的死亡仍结束会话。

## 验收样例

**代码已实现，待实测（0.2.63）**：NPC 短步必须用发键后不同导航序列确认，重复帧只能等待；按住 W 最长一个短步，之后松开等反馈。1.5 秒仍无新序列按数据失效停止，不以视觉代替缺失数据。新序列报告无位移才进入既有退避与绕障；目标、地图或阶段变化取消旧短步。短步移动确认、进入 5 码、打开对话与实际交付是不同反馈。

同一 NPC 两个可接任务均接完后才离开；旁边第二个 NPC 也被访问；刚接就完成的先交并接后续；已有任务不重复领取；击杀但没捡任务物品仍留在目标阶段；交付后新任务进入下一轮或即时后续处理。

**0.2.65 代码修订，待实测**：NPC 精细接近新增朝向核对与目标标记距离趋势；短步没有接近时停步重规划，最多两次。地图标记不是 NPC 精确位置，到标记附近却未收到原生 5 码范围时挂起；已经收到范围回执则停稳重试互动，不再为重试对话向前走。回归包含 2026-11-16 16:09 三次走远样本；实机交付未验证。

**实机证据（2026-11-17 15:28，构建 268）**：运行 `20261117T072826-653dea9d` 在 15:28:36 收到 NPC 范围回执，15:28:39 确认 90893 交付，15:28:45 正常结束。启动前保存的轮次中 90893、90895 均挂起；旧准备逻辑只解除 90893，剩余 90895 被跳过，主控又只汇总本进程挂起而漏报。用户观察为绕行后交付；本轮日志仅含普通接近，没有分割绕障/自动标定事件，不据此验收那些分支。**0.2.69 代码修复，待实测**：新一轮恢复全部未完成项，扩展 schema 6 回报挂起数量，保留 schema 1–5 解析；补两项连续交付、已交项过滤、接后续、轮内不无限重试及历史挂起摘要回归。
