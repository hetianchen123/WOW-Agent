# Wow 开发与实机回归

把“玩家如何观察、操作、确认结果”转为可验证的脚本状态机。此 skill 服务于开发和排错；游戏运行依靠本地脚本，StartLux 在决策点选择候选动作，Qwen3-VL 按需提供视觉观察。不要让日常任务推进依赖用户反复回到聊天。

## 开始工作

1. 在 WowAgent 项目根目录工作；当前项目为 `/Volumes/Mac SSD1/projects/wow-agnet`。其他位置使用前先确认仓库身份。
2. 阅读当前日志及相关代码，确认运行版本、任务阶段、键位、目标身份和最近一次有进展的动作。用户手动成功的操作是重要的对照样本。
3. 按当前问题读取参考：
   - 跑地图、飞行、卡住、小地图、镜头：[移动与视角](references/navigation.md)。
   - 找怪、面对目标、攻击距离、尸体拾取、南瓜类物件：[战斗与拾取](references/combat-loot.md)。
   - 远程与近战站位、战斗镜头、切换目标、团本和大秘境：[战斗站位与选敌](references/combat-positioning.md)。
   - 附近未知任务、批量领取、立刻可交任务、后续任务：[任务轮次](references/quest-rounds.md)。
   - 键位、代码入口、测试、部署和实机结论：[实现与验证](references/implementation.md)。
   - 无限服分支、北郡网格、训练师、天赋和输出宏：[无限服回归](references/forever-leveling.md)。
   - 正式服目标、任务、战斗、跑图和镜头接口的可用性：[正式服插件 API 参考](../../docs/retail-addon-api.md)。

## 开发、测试和实机复跑

1. 从最新启动日志、任务日志和同一 run 的证据定位断点。分开核对磁盘插件、实际加载的 build、主控源码和游戏回执。旧回执只用于复现和对照。
2. 修复后跑关联的 Python 或 Lua 回归。修改 Lua 时备份并安装改动、核对版本，然后在游戏里 `/reload`。只改 Python 时下次启动主控即可载入。
3. 每次需要实机验证的改动完成后，由开发者进游戏点「一键准备自动任务」，核对任务 ID 和准备结果，关闭准备面板并启动一次本地脚本。使用可用的受支持命令行入口或「WoW 键鼠」菜单。用户负责 macOS 系统权限的批准，开发者可操作插件准备和已有权限下的一次性启动。
4. 角色的跑图、对话、战斗和交付由脚本执行。启动后保持魔兽前台，查看日志直到成功、挂起、退出或确需用户处理系统权限。正常停机先核对原因再修复复跑。报告实机结果时给出 run ID 和任务回执。

[实现与验证](references/implementation.md#排错与验证)给出日志、测试、部署和启动细节。[任务轮次](references/quest-rounds.md)与[移动与视角](references/navigation.md#局部分治旅行2026-11-18-用户要求已有实机回执)记录当前任务接续和室内网格、室外直线的分治证据。

## 共用约定

- 用户偏好：能飞优先飞，其次地面坐骑，最后步行；进入建筑、短距离精确互动和战斗按场景降级。附近任务先批量领、逐个做、批量交；立刻可交的优先交并接后续。
- 视角操作平缓且有停顿，不频繁高速左右晃动。取消鼠标网格扫屏、随机悬停等盲找降级；鼠标只能移动到已有识别依据的候选位置。找不到怪不能自动改成鼠标扫物件；缺少定位能力时报告缺口，不以盲扫填补。
- 每个动作都定义前置条件、有限动作、反馈、失败恢复和退出条件。按键发送成功不等于施法成功；施法成功不等于拾取成功；物品拾取不等于任务已完成。
- 游戏公开、非受限的结构化状态优先；地图标记表示候选位置，不表示通行路线或实际可交互距离。缺失/受限值保留为未知，不能转换成 0、否或成功。
- 玩家位置、角色朝向、镜头朝向、屏幕坐标、小地图方向和世界地图坐标分别处理。不同来源的状态可能不同步，靠目标身份和帧序列校验。
- 角色定位与可通行判断分开；草丛、水面或特效遮住脚点不是停止规划的充分条件。原生位置/已核验镜头锚点、实体障碍、视觉遮挡、已走通路径分别取证。NPC 以接近区域和原生互动回执为准，不要求走到脚底或精确图钉。遮挡试探必须有预算和位移反馈，不把整条候选当作已验证通路。
- 静态 NPC 缺失、分阶段身份变化或附近选错对象时，优先修复运行时自动找人、验距和核对任务对话的流程。地图图钉和现有 Grail 缓存只提供接近位置。开发验证以脚本实际选中、对话任务 ID 和游戏任务状态为准。
- 用户纠正（2026-11-17）：建筑、特效会使地面占比很低，地面占画面的比例不能作为继续观察、标定或规划的门槛。局部可用就继续：检查局部匹配、独立几何验证、短段净空和真实位移，不要求整幅清楚或脚点可见。占比只作诊断；局部未知、实体障碍、水域和测量失败分别处理，不能用整体占比替代局部证据。
- 建筑导航须区分门洞候选、当前支撑表面、已穿越门户和任务到达。`IsOutdoors`、任务图钉和“closed door”检测词都不能单独确定通路或楼层。台阶不能套用平地投影；已标定平面可先选择可达观察点，再重拍。逐项实现和实测范围见 [建筑导航清单](../../docs/building-navigation.md)。
- 门洞底部检测框可能包含门框脚部、门槛和门外地面；到达这些位置不能作为穿门回执。门内地面暂不连通时，先到已测得且可达的近处观察点，再重拍；引导方向使用门内可见地面，不能追着门板或框角走。检查点识别正确仍须另验整段通路。
- 局部识别出的台阶必须传回同帧建筑布局并保留为独立表面；接近点可位于其任一可达侧，不能固定取检测框下边。靠近台阶的位移只确认观察位置，不确认上楼、穿门或楼层；墙饰/家具误叫台阶仍是待处理的模型错误。
- 局部坡面允许独立测量，不能仅因上坡高度变化超过固定阈值重置标定。图像几何与可变化的原生高度分别拟合、用另外的位移验证；固定高度不提供坡度或楼层证据。已发短步在位置、方向及范围得到核对后，若显示表面变化，停用旧投影并重新观察测量；下落、异常位移和失联仍中断，不能因重新测量重置总预算。
- 常规动作由确定性脚本完成。失败后再升级观察和决策；不要反复调用模型代替缺少反馈的重试。
- 托管流程不得要求用户手工走标定点、点击角色脚点或登记 NPC 接近区域。正常入口使用自动地面几何测量、独立位移验证和自动目标搜索区域；人工工具仅用于开发对照。无法测量时有限恢复/挂起，不把未知尺度或任务图钉包装成精确坐标。
- 当前用户指定“分割模型识别 → 本地搜索 → 测量标定后转地图坐标”，不接大模型 API；`route_planner.enabled=false`，历史 DeepSeek/GLM 实验保留为证据，不自动回退到云端。当前使用本地检测＋SAM2＋语义分割，完整场景验收仍未完成。固定侧偏不能冒充视觉路线，图像路点不能冒称精确世界坐标；未标定时不得按图像路点移动。近期实走轨迹可依据独立的原生位置回执进行有限回退，不能称为图像标定成功。当前识别、几何及实机状态分别见移动参考。
- 保留现有键鼠授权、焦点检查、停止和按键释放机制。skill 本身不启动游戏操作、不延长会话权限。用户要求实测时沿用既有授权范围。
- 用户要求（2026-11-18）：插件提供临时隐藏动作栏等干扰 UI 与恢复入口。只修改所选界面的显示和鼠标响应，保留动作绑定、色条、小地图、任务对话和复活窗口；按原状态恢复，战斗中恢复延后到脱战。不能用隐藏 UI 的意图推断截图中所有 UI 已消失；模型仍须按实际画面及已确认状态处理。

## 维护方法

每次新增操作能力或修复实机失败，更新对应参考中的最小必要规则，同时补充行为回归测试。将记录明确标成：**用户要求**、**日志/手动实测证据**、**代码已实现但待实测**、**待验证假设**。不能把通过单元测试写成已在游戏成功。

保留可重现的关键状态、动作与反馈，避免堆积整份聊天或日志。新证据推翻旧规则时修订旧规则，不仅追加例外。不要把特定任务 ID、职业技能、某个客户端版本的限制写成所有版本通用规律。运行脚本不会自动读取本文；新增准则必须落实到代码和测试才会改变游戏行为。

公开视频的记录标为 **录像观察**，保留版本、场景、视角和时间点。由观察提炼的操作标为 **玩家操作参考**，落到当前客户端或脚本的效果由本机实测确认。
